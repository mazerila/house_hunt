# House Hunt

A methodology + toolkit for doing serious due diligence on French house listings (houses, terrains, teardown plots), developed during a real search in Hauts-de-Seine. The examples and hard-learned lessons below come from actual listings vetted with it.

Your own investigation data (per-listing notes, verdicts, downloaded records) lives under `private/` — gitignored, never published. See `private/README.md` for the layout.

## Privacy — no PII to third parties

Never send the user's personal identifiers (name, private email, phone, employer, exact current address) to third-party or open APIs — not in User-Agents, not in query params (e.g. the RNB `from=`), not in webhooks, and not embedded in web-search queries or fetched URLs. Concretely:

- Outbound requests use the **generic UA** `house-hunt/0.1`. A contact email is included **only** if `HOUSE_HUNT_FROM_EMAIL` is explicitly set in the gitignored `.env` (opt-in, never hardcoded in source — this repo previously leaked a private email as a hardcoded default; don't reintroduce one).
- Credentials for the user's own accounts (API keys, mail app-passwords) live **only** in the gitignored `.env`, are sent only to their own provider, and are never printed, logged, cached, or committed.
- Public-record data _about properties_ (cadastre, DVF, permits, seller SIREN) is fine to query and store; the rule is about the **user's** identity travelling outward.
- When drafting outbound artifacts (emails to agents, forms), leave identity fields as placeholders (`[Prénom NOM]`) unless the user explicitly says to fill them.

### RNB — Référentiel National des Bâtiments

- Docs: https://rnb-fr.gitbook.io/documentation
- Map: https://rnb.beta.gouv.fr/carte
- API base: https://rnb-api.beta.gouv.fr/api/alpha/buildings/

The RNB is the French national building registry: it gives every building one **unique, permanent ID-RNB** and acts as a _pivot identifier_ to cross-reference 38+ databases — including **DPE**, **fichiers fonciers**, **cadastre / parcelles**, **BD TOPO (IGN)**, **BDNB**, and the **registre des copropriétés**. Open data under licence Etalab 2.0. (APIs are alpha — request/response formats may change; the IDs are stable.)

- **ID-RNB:** 12 characters in 3 groups of 4 (alphanumeric, case-insensitive, non-significant — carries no commune code). Example: `NHDE-2W8H-E3X3`.
- **Map UI:** search an address or click a building to read its RNB ID, status, addresses and linked parcels.
- **Buildings API:** consult a building by RNB ID, search by location / address / cadastral parcel, list by INSEE code, or get a differential since a date. Returns a point + footprint (WGS 84), status (`constructed` / `notUsable` / `demolished`), BAN address IDs, cadastral parcels, and `ext_ids` linking BD TOPO / BDNB. Rate-limited to 20 req/IP/s; no key required (add `?from=you@example.com` to be notified of API changes).
- **Other tools:** vector tiles, ADS API (permits / autorisations du droit des sols), national & departmental export (full DB download), OGC API Features, and a sandbox.

**Why it's useful here:** the DPE XML carries an `id_batiment_rnb` field — resolving a listing's building in the RNB ties it to its **parcels** (e.g. F 299 / F 300) and pulls cross-referenced **DPE / fichiers fonciers** records for the same building.

## Parcel due diligence — required checks

**Run each listing analysis in its own subagent.** When the user asks to analyse a case, dispatch a background `general-purpose` agent per listing (so several can run in parallel), instructing it to follow this checklist, use the repo scripts + open APIs below, respect the privacy rule, then **write the dossier to `private/listings/<slug>.md`** and update `private/list.md`. Tell the user to hit **Réimporter** in the dashboard afterward; correct any misread numeric field (surface/land/price) via the dashboard (it becomes a protected override).

**Report template** (`private/listings/<slug>.md`): H1 with address + postal code · a `Status: **…**` seed line (maps to dashboard status: "visité"→visited, "visite prévue"→visit-planned, "offre"→offer, "rejet…"→rejected, else researching) · `## Identity` bullets (include `Prix demandé: **N €**` when known — the importer reads it) · `## DPE` · `## Documents au dossier` *(once the seller hands over PDFs — one line per file: what it is, its date and operator, plus what's still missing)* · **`## Résumé — points positifs / négatifs`** (a short bullet list, positives first then negatives — the user wants this on every report) · `## Verdict` · `## Open items`. Prices: put the asking price in the md; the buyer's `Prix min` / `Offre acceptable` are set in the dashboard (fields `price_min` / `price_offer`) — seed reasoned suggestions there and explain the basis in the verdict.

**Listing folder** `private/listings/<slug>/`: holds the source documents (PDFs) and a `photos/` subfolder for house photos (the dashboard shows these as a gallery). **Every listing gets both photo sets** — the buyer's own visit shots (`IMG_*`, HEIC is fine, the dashboard transcodes it) *and* the portal's ad photos (`annonce-NN.jpg`, harvested as described below): the ad is staged and seasonal, the visit photos are the real state, and the gap between them is where the ad's claims break. Extract exterior/plan images from the diagnostics PDFs with `pdfimages -png` / `pdftoppm` into `photos/`. The dashboard auto-assigns each listing a short sortable code (H01, H02, …) — no action needed. Any announce URL you put in the md note is auto-detected in the drawer's **Annonces** section, so include the source listing URL when you have one.

Run all of these for every listing. Cite the source for each fact, and keep **data facts separate from on-the-ground reality** (the cadastre can lie about frontage).

1. **Locate the exact parcel.**
   - Coordinates (convert DMS → decimal) → apicarto cadastre _point-in-parcel_.
   - Address → `scripts/rnb_lookup.py "<addr>" --print` (or BAN geocode).
   - Fuzzy ("section X, ~N m²") → apicarto _section scan_, **via `curl` on the full JSON + local filter** — a WebFetch summary truncates and silently drops parcels (it missed the real match on Antony section CM).
   - Confirm cadastral `contenance` ≈ listed surface; a >~5 m² gap ⇒ possible division-in-progress.
   - **Ambiguity gate:** if several parcels match _and they fall in different zones_, do NOT commit to one — flag it and ask for the exact pin. (Antony CM straddles U1g\* pavillonnaire **and** the Antonypôle OAP; guessing the parcel flips the verdict between candidate and reject.)

2. **Planning layers** — apicarto GPU at the parcel point → the red flags:
   `zone-urba` (zone + `E/T/H/A` indices), `prescription-surf` (**EPP/EBC/OAP**, emplacement réservé, gare-perimeter), `assiette-sup-s` (**carrières PM1**, **ABF AC1 abords MH**).
   Also sample the **adjacent parcels' zone/prescriptions** — an OAP/gare sector means you vet _this_ plot but inherit years of construction and densifying (collective/social-housing) neighbours around it.

3. **Slope** — always check elevation via **IGN RGE ALTI** and compute the % grade over the plot depth. A listing touting "sous-sol total" is usually signalling a slope. Slope = costs more to build **and** sells for less.

4. **Frontage / geometry** — derive it from the parcel vertices but **treat it as provisional**: never conclude "not a flag-lot" from the cadastre alone; always flag it for Street View + the bornage. (Fontenay P218 read as a normal ~10 m front on the cadastre; on the ground it was a narrow back-lot.)

5. **DVF** — geo-DVF S3 CSV: the parcel's own sale (= seller cost basis / negotiation anchor) + same-street comps (= value read). **Standard (user preference):** build a **DVF comp table** into the `## Marché` section — same-commune, similar-size *closed* sales (address · year · price · surface · terrain · €/m²) + the **median €/m²** and where the subject sits — and, when the user states an offer, **record it in the dashboard** (`price_offer`, plus `price_min` = estimated seller floor, and `status: offer`).

6. **DPE registry (ADEME) — mandatory for any _house/apartment_ listing** (n/a for bare terrain). Two uses:
   - **Locate** a withheld-address listing by fingerprint: query `etiquette_dpe` + `type_batiment` + commune, then match build year / energy / surface. **Use WIDE surface bands and match on several traits** — advertised and DPE surfaces disagree routinely (Bagneux: ad said 165 m², DPE 194 m² → a 150–180 filter missed the real house and matched the wrong one). Cross-check against the listing's map/street clues; the ambiguity gate applies here too.
   - **Confirm + harvest — always pull the FULL record** (by `numero_dpe` or address) once a candidate exists, _before_ the verdict: it carries **`id_rnb`** (cross-anchor with the RNB building = identity proof), the **true surface habitable**, `periode_construction`, the exact **heating/ECS systems and their ages**, the **envelope scorecard** (walls/windows/VMC/confort d'été = the works map), annual cost estimate, and validity dates. A fresh DPE date also reveals when the seller started preparing the sale.
   - **Costing renovation:** an **audit énergétique** (`private/listings/<slug>/`) carries costed work scenarios reaching a target DPE — but its figures are **regulatory/indicative and understate real Île-de-France quotes** (windows often **~2× low**; ITI "insulation-only" lines hide the placo/finishes in a separate "induits" line). Recost against the market (ITI ~40–90 €/m² posé; PVC DV posé ~900–1 200 €/unit standard, more for large/portes-fenêtres) and **add non-energy works the audit ignores**: électricité (DDT anomalies), amiante liste B removal, cuisine/SdB, toit-terrasse étanchéité, rafraîchissement. A full IdF reno of an older house runs **~150–210 k€**, not the audit's ~50 k€.
   - **Round-trip value framing:** factor **~45 k€ notaire (buy)** + **~20 k€ agence (resell)** into value/negotiation. Once heavy real works + ~65 k€ of round-trip fees are in, the **flip spread usually collapses** — the case for an older heritage-constrained house is to **occupy it** (buy low, do a measured comfort+kitchen pack, keep a recent boiler), with the **plot as the real long-term asset**.

7. **Permits** — France Cadastre / basedespermis for a granted PC or permis de démolir on _this_ parcel: formal number, applicant (private vs _marchand_), dates, and whether **purgé de tout recours**.

8. **Risques Géorisques — la passe que l'écran automatique ne fait pas.** `enrich.py` couvre RGA argile et cavités ; le reste se tire à la main de l'API `georisques.gouv.fr/api/v1` et mérite une section `## Risques` dans le dossier : **`gaspar/catnat?code_insee=`** (le nombre et surtout les **années** des arrêtés sécheresse — c'est ce qui qualifie le risque argile : 1 arrêté à Bailly contre 6 à Noisy-le-Roi pour la même « exposition forte »), **`radon?code_insee=`**, **`mvt?latlon=&rayon=`** (mouvements de terrain), **`ssp`** et **`installations_classees?latlon=&rayon=`**. Format `latlon=LON%2CLAT`. NB : l'endpoint `sis` renvoie 404, utiliser `ssp`.
9. **Verdict** — buildability + **all-in price** + **self-build fit**; then update `private/list.md` (`## Active` / `## Rejected`, one-line reason). Price the **serviced, cleared** plot, not just the land: add **viabilisation/raccordement €5–30k** (distance-to-networks driven), **taxe d'aménagement 5–8%**, any **demolition**, and a **25–30% build contingency** (self-builds overrun) — plus double-carry (current housing + loan interest) over a **32–48-month** build.

### Seller documents (DDT, Carrez, audit, ebook agence) — the reconciliation pass

When the owner or agency hands over PDFs, **drop them in `private/listings/<slug>/`** (the dashboard's Documents section picks them up, see below) and **re-run the dossier against them**. These documents are the first *contractual* facts in the file — they routinely contradict the portal ad, and always in the seller's favour. Extract text with `pdftotext -layout`. Every item below produced a real correction on Noisy-le-Roi H05 (2026-07):

1. **Re-derive the surface from the Carrez certificate, then recompute everything.** The ad's headline m² is often the **surface au sol**, not habitable — H05 advertised 146 m² against a Carrez of **136,07 m²** (−7 %). The certificate's per-room table also exposes **mansardé** rooms (Carrez ≪ surface au sol under 1,80 m ⇒ a "bedroom" that isn't a full one). **Recompute €/m² and redo the DVF median comparison** — H05 moved from "7 % under the median" to "exactly at the median", which flipped the negotiation. DVF `surface_reelle_bati` is comparable to Carrez, so the comp table stays valid; only the subject's row changes.
2. **Take the `numero_dpe` from the DDT and pull the FULL ADEME record** (`qs=numero_dpe:"…"`). Never trust the ad's DPE letter alone: it hides the **energy vector**. H05's ad implied gas; the record showed **panneaux rayonnants électriques + poêle bois en appoint** and an old **ballon électrique** — a different house, financially. The record also gives `id_rnb`, the envelope scorecard, `periode_construction` and the déperditions split (which names the real works targets — for H05, air-renewal 38 % and walls 29 %, *not* the already-replaced windows).
3. **Read the électricité report's anomaly table AND the "informations complémentaires" (art. B11).** Anomaly count alone understates it: B11 is where "**aucun dispositif différentiel ≤ 30 mA**" appears, which means an original-era tableau. Missing earth on circuits + no 30 mA + traces d'échauffement + no LES in the bathrooms = **8–15 k€**, a safety item, not a formality.
4. **The assainissement report can carry an imposed work.** Read the *Observations* line — H05's says the water utility requires **creating a boîte de branchement EU** on the public side (1,5–4 k€), and the report was already filed with the intercommunalité. That is a negotiation lever, not a nicety.
5. **Amiante "néant" is worth stating loudly** — it removes the single biggest hidden cost. (The vente report doesn't cover works/demolition; say so.)
6. **In a lotissement, ask for the ASL's PV d'AG *and* the cahier des charges — they are two different documents and both bind.** The **PV** gives the real cost of belonging (Noisy H15's Domaine du Parc: **504 lots, 103 €/lot/an** — against 2 000 €/an for Jouy H09's résidence, so an ASL is not automatically a burden) plus what is brewing (voted works, a tree disease under watch). The **cahier des charges** is private law, opposable between colotis, and **survives the PLU**: H15's 2005 text imposes white windows, fences ≤ 1,50 m, hedges ≤ 2 m, masonry garden sheds only, no aerials — and above all **every DP/PC must go to the ASL *before* the mairie**. It also sets the extension cap, and there it can be *generous* (**40 % of the SHON** at H15, against the 20 m² of Jouy/Montebello) — so read it before assuming either way. Post-2005 equipment (PAC, solar) is usually absent from the text and falls back on the general "aspect extérieur" clause, cumulated with any ABF opinion.
7. **The agency's own ebook/plaquette is more honest than its portal ad.** Its grid gives **état général / extérieur / intérieur**, **mitoyenneté**, **honoraires** (⇒ net vendeur), and the direct negotiator. H05's portal ad said "Entretenu"; its own ebook said **« Moyen / Moyen / À rafraîchir »**. Quote the ebook, it's the seller's admission.
8. **Audit understatement still applies** (see the DPE section above): the DPE's own work packs are regulatory figures — recost against IdF market rates and **add the non-energy works the pack ignores** (électricité, salles d'eau, rafraîchissement, extérieur under ABF).
9. **A document that exists can still be blank where it matters.** Mareil-Marly H13's ERP was in the DDT — and the line *« l'immeuble a-t-il donné lieu au versement d'une indemnité à la suite d'une catastrophe naturelle ? »* had **neither box ticked**, on a house in *argile forte* with 5 arrêtés sécheresse. Read the **boxes**, not the table of contents; and check the ERP's **6-month validity** (H13's expires 09/09/2026, so it must be reissued at the compromis). Same reflex on the audit énergétique: H13's prescribes **ITI while ITE was legally possible** (no servitude at all) — ITI is cheaper on paper but eats 5–7 m² of habitable surface, which at 5 000 €/m² is the whole price difference; and its total **excludes the travaux induits** it names in its own disclaimer.
10. **Inventory what is MISSING.** H05's DDT had no **ERP (état des risques)** — mandatory at compromis, and the only route to RGA argile / carrières / CatNat. Also chase taxe foncière, ASL charges, and any combles-conversion authorisation. List these in `## Open items` and tell the user to demand them.
11. **Then rewrite the dossier honestly**: add a **`## Documents au dossier`** section (each file, what it is, its date + operator), revise the works table and the verdict, **restate any earlier conclusion the documents overturn** (don't quietly edit it away — H05's verdict explicitly says the "0–40 k€ cosmétique" estimate was wrong and why), reseed `price_min` / `price_offer` via the dashboard API, and update `private/list.md`.

**Buyer filters** (an example profile — adapt to your own constraints): self-buildable (not CCMI / "loi 19-12-1990"-locked), flat, wide frontage, no carrières if avoidable, outside a dense OAP, ≤ ~30 min from [your anchor point — work/school/family], low social housing. **No heritage-locked properties** (ABF abords / ensemble bâti remarquable / EPP on the building): unmodifiable + thin resale = unacceptable illiquidity (the Cherrier lesson — long time-on-market is the exit preview).

**Two lanes:** a granted + purgé + _transferable_ PC de-risks buildability but carries a ~€60–100k premium (anchor on the seller's DVF cost basis; don't pay it twice). A clean raw/teardown plot lets you file **your own** PC — via a _condition suspensive d'obtention du PC_, or a positive **CUb** that freezes the rules 18 months — and design your own house: the better lane when you're patient.

## Analysis tools & endpoints

Repo scripts (use `./.venv/bin/python`): `scripts/rnb_lookup.py "<address>" --print` (address → RNB buildings + parcels), `scripts/compare_dpe.py <a.xml> <b.xml>` (DPE 3CL XML diff).

**`scripts/enrich.py` — the automated red-flag screen (run it after every import).** Stdlib-only; re-runs the four checks that actually decide a listing and writes them into the db as *structured* fields, so the dashboard can badge/sort/filter instead of burying them in prose:

```bash
python3 scripts/enrich.py              # all listings
python3 scripts/enrich.py --id h10     # one (id or code substring)
python3 scripts/enrich.py --force      # bypass the 30-day disk cache (.cache/enrich/)
python3 scripts/enrich.py --dry-run    # print, don't write
```

Per listing it reads the note's `Coordonnées:` line (falling back to geocoding the H1 address) and stores under `enrichment`: **PLU zone**, **prescriptions**, **servitudes**, **RGA argile**, **cavités < 1 km**, a computed **`flags`** list (`red`/`amber`/`green`) and **`heritage_locked`** (true if any AC1/AC2/AC4 — the buyer's hard filter), plus the **commune DVF median & p75 €/m²** and the **commute** to each anchor. It caught a lisière on H07 and a carrières PM1 perimeter on H04 that hand analysis had missed — **always run it before writing the verdict**.

The dashboard then shows a **Drapeaux** column (badge counts, full labels on hover), a **`Sans verrouillage patrimonial`** filter, and an **Écart** column = post-works value − all-in cost, where all-in = `prix × 1,08 + travaux` (8 % de frais de notaire, à la charge de l'acheteur, calculés sur le prix du bien seul — pas sur les travaux). **Le prix retenu est l'offre de l'acheteur (`price_offer`) dès qu'elle est renseignée**, le prix demandé seulement à défaut — l'écart répond à « qu'est-ce que ça donne si je l'achète à mon prix ? », pas à celui du vendeur. **The Écart deliberately shows `travaux ?` instead of a number until `works_total` is set** — price-vs-value with no works figure reads as a big green bargain on a house that needs gutting. The post-works €/m² defaults to the commune's **DVF p75**; override it per listing via `value_m2_post` (drawer field "Valeur post-travaux (€/m²)") when p75 flatters the property — needed on H10 (13-14 % slope, unfinished floor) and H08 (Fourqueux merged into Saint-Germain-en-Laye, whose sales inflate the p75). **When the buyer states an absolute resale ceiling** ("revente max 800 k€"), encode it in the same field as `plafond ÷ surface habitable` and say which €/m² that came to — the tooltip labels the source *manuel* vs *DVF p75*, so the two never get confused (done on H02 → 4 916 €/m² and H11 → 5 654 €/m²).

**The buyer's own numbers outrank the derived ones.** A stated max purchase price goes in `price_offer`, a stated works ceiling replaces the whole `works` list with a single explicit line, and a stated resale ceiling goes in `value_m2_post`. These are hypotheses the buyer owns — never quietly average them with a DVF read, and when one of them single-handedly flips the ranking (H02's 800 k€ ceiling moved it from first to last), say so and ask whether the figure is post-works.

**Commute anchors** live in `private/anchors.json` (**gitignored** — it holds the user's work locations). Only coordinates and a neutral label are stored. Straight-line km by default; set `HOUSE_HUNT_NAVITIA_KEY` in the gitignored `.env` for real door-to-door transit minutes (free key at navitia.io). Never put these addresses in a tracked file, a web-search query or a User-Agent.

**Dashboard (local GUI):** `python3 scripts/dashboard.py` (stdlib-only, port 8420 — **if the port is already taken it now says so and names the PID holding it**, instead of dumping a `[Errno 48]` traceback; note that a `127.0.0.1` bind and a `--lan` (`0.0.0.0`) bind of the same port behave differently, so a test that starts fine on localhost can still fail with `--lan`) serves `scripts/dashboard.html` (French UI, dark/light, monochrome icons) at `http://localhost:8420`. **Every list remembers its filters and its sort across reloads** — Annonces (recherche, statut, commune, drapeaux, note + the two sort levels), Brouillons (les statuts cochés + the three sort levels + the dragged column widths), Critères (partie active, filtre, annonce cochée) and the Villes ciblées sort, each under its own `hh-*-view` key via the shared `prefsGet`/`prefsSet` (localStorage, per browser, never server-side). Reads are defensive — `setSelectIfValid()` ignores a saved value whose `<option>` no longer exists — so a renamed filter or a commune that lost its last listing can never leave a list stuck showing nothing. Two things stay deliberately transient: the **Archives** switch (a reload always lands on the active list, so you can't forget you're in the archive) and the drawer. *(The Villes ciblées sort used to be transient too; it is now remembered, and **↩ Mon ordre** still clears it in one click.)* It imports `private/listings/*.md` into `private/dashboard_db.json` (gitignored) — one record per note, id = filename slug. Statuses: `researching | visit-planned | visited | offer | rejected`. Heuristic-derived fields (price, surface, land_surface…) are re-derived on each réimport **unless** the user edited them in the GUI (tracked in the record's `overrides`); rating/status/tags/verdict/comment are always user-owned. So: after researching a listing, write the note to `private/listings/<slug>.md` (H1 with address + postal code, `Status: **…**` line, `## Identity` bullets, `## DPE` section) and tell the user to hit Réimporter — don't edit `dashboard_db.json` directly. The record also carries **`agency`/`contact`** fields, seeded from `## Identity` bullets (`Agence: **…**`, `Contact: **…**`) and editable in the drawer as string overrides (a manual value sticks across réimport; clear it to re-derive from the md). **Both grids carry a row thumbnail — the façade — because a code and an address don't let you recognise a house at a glance.** Annonces: a `photo` column (first, added to existing installs by the `_mig_photo_col` one-shot since the visible set is persisted). Brouillons: a column right after the `#`. The picture comes from **`photos/cover.jpg`** in the listing folder — a *derived* file, excluded from the gallery by `is_cover()` so it never shows twice — falling back to the lowest-numbered `annonce-NN`, then to the first image. Drafts have no folder, so their thumbnail is the ad's hero shot saved as **`private/thumbs/<draft-id>.jpg`**, served by `/draft-thumb/<id>`. **Do this for every new listing and every new draft** (see below for how). Each listing folder's `photos/` gallery is shown in the drawer; put portal shots there (see below). Under it, a **Plans** section holds the floor plans, plan de masse and cadastral extracts, which answer different questions from the photos: an image counts as a plan if it sits in **`private/listings/<slug>/plans/`** (the reliable way — placement wins) or if its filename contains `plan`, `cadastr`, `croquis`, `implantation` or `masse` (`is_plan()`; the hints stay narrow on purpose — adding "façade" would swallow real photos). Both galleries share one lightbox, plans sorted last, so the arrows still walk the whole set. Under the gallery, a **Documents** section lists every **PDF** found in `private/listings/<slug>/` (and an optional `<slug>/docs/`) — click one to open it in an in-page viewer (browser PDF renderer, ‹ › to step between documents, *Nouvel onglet* / *Télécharger*, Échap to close). Sellers' filenames are opaque, so each row shows a **derived French title** above the filename (`doc_title()` keyword-matches DDT, DPE, audit énergétique, Carrez/surface, amiante, CREP, termites, électricité, gaz, assainissement, ERP, taxe foncière, copro/PV AG, devis, G2, urbanisme, cadastre, ebook; unmatched names fall back to the filename — extend `DOC_TITLE_RULES` for new document types). So: drop the seller's PDFs straight into the listing folder and they show up — no naming convention, no import step.

A third tab, **Critères**, is the decision check-list, backed by the tracked **`criteria.md`** (generic knowledge, no PII — committable like `towns/`). It is split in three, and the split is the point: **Drapeaux rouges** (the short list read first, on site — signals that make you cancel and go look at something else: a fissure en escalier, a plancher out of level, mérule, water arriving on the plot, a price 25 % under the street with no stated reason; one is enough to stop spending) versus **Immuable** (commune, desserte, parcelle, règlement, relief, and the parts of the building you can't move — a defect here disqualifies or is paid in resale discount) versus **Modifiable** (what money repairs — a defect here is a costing line and a negotiation lever, so those items carry indicative IdF cost ranges). Items tagged `[éliminatoire]` are the hard buyer filters; `[visite]` ones can only be checked on site — both render as badges. Format is `## part` → `### group` → `- **label** — detail \`cost\``; add or reword items by editing the md, ids are hashed from part/group/label so existing ticks survive — which is why a new part can be added without disturbing them. A part's colour comes from `critPartKind()` matching its heading (`drapeau|rouge` → dark red, `immuable` → red, anything else → green), so a fourth part only needs a title the regex knows. Pick a listing in the tab's selector to turn it into a **visit check-list**: clicking an item cycles *à vérifier → ✓ validé → ✗ problème*, stored per listing in `criteria_state` (user-owned, survives réimport), with filters (non cochés / problème / validé / éliminatoires / à vérifier sur place) and a progress counter.

Five rows of the town sheets are **measured, not typed**, and regenerated by **`scripts/enrich_towns.py`** (stdlib-only, cached, idempotent — re-running changes nothing): `Prix maison DVF (2023-25)` and `Terrain médian (DVF)` from **geo-DVF** closed house sales, plus `Cambriolages (‰ logements)`, `Violences (‰ hab.)` and `Dégradations (‰ hab.)` from the **SSMSI base communale de la délinquance** (data.gouv, année 2025). It upserts them as ordinary Repères bullets next to their related rows, so the md stays the source of truth and the tab needs no code change. The older `Prix maison (2025)` / `Terrain maison (indicatif)` rows are kept alongside for comparison. Run `python3 scripts/enrich_towns.py [--id chatou] [--force] [--dry-run]`.

The same script also writes **`towns/price_history.json`** (tracked): the **median €/m² year by year, 2021-2025**, on exactly the basis the Repères row uses (aggregated per `id_mutation`, tiny and symbolic sales dropped), so the chart and the table can never disagree. geo-DVF starts at 2021 — 2019/2020 return 404. The Villes ciblées tab renders it as a **multi-series line chart** (`/api/price-history`, inline SVG, no library) above the comparison table: it follows the tab's own show/hide and order, is **capped at 8 communes** because that is where the validated palette stops, and ships a legend, a crosshair tooltip carrying each year's **n**, and a *Voir les chiffres* table view. Two rules worth keeping if it is ever touched: the hues are the validated categorical order checked against this dashboard's own surfaces (`scripts/validate_palette.js` in the `dataviz` skill — three light steps sit under 3:1 contrast, which is why the legend and table view are not optional), and **a palette slot is held per commune** (`phSlots`), so hiding one never repaints the others.

**Two findings these rows surfaced, worth remembering:** burglary is *inversely* correlated with density here — communes under 1 500 hab/km² average **11,1 ‰** against **7,1 ‰** for those over 3 000, while violence runs the other way (0,33 ‰ vs 1,50 ‰). The quiet affluent village is the high-burglary profile (Mareil-Marly **20,7 ‰**, Marnes-la-Coquette 17,5, L'Étang-la-Ville and Bailly 13,4). **Noisy-le-Roi is the notable exception** — village density (1 391) with the lowest violence of all 26 (0,65 ‰) and burglary at 6,01 ‰. ⚠️ ‰ rates are volatile on small communes.

A fourth tab, **Brouillons**, is the shortlist-before-the-shortlist: ads spotted but not yet instructed. Unlike a listing it has **no md file and no research** — the row is typed straight into the grid (each cell is a bare input that saves on blur; Échap annule, Entrée valide) and lives only in `private/dashboard_db.json` under `drafts`. Columns read left to right as the triage goes: **`#`** (row number — the *displayed* position, filled by `applyDraftFilter()`, never a stored field: it renumbers on every sort and skips filtered-out rows so the list always reads 1, 2, 3…; smaller and dimmer than the data, not sortable, hidden in phone card view), then **Statut**, then **Prio**, then the ad's own facts. Fields are deliberately few: code `B01…` (auto, never reused), **priorité d'appel/visite** (`priority`, empty / `p1` / `p2` / `p3` — three levels on purpose: a longer scale gets used as a ranking and stops meaning anything; the column is colour-coded, P1 warm through P3 quiet, and an untriaged row sorts last like any blank), lien d'annonce (with a ↗ that opens it), prix, ville, surface habitable, terrain, téléphone, agence, **date/heure de visite** (`visit_at`, built by `draftVisitCell()` as a native date input plus **one time select, 09:00 → 21:00 by 5 minutes** (`VISIT_FROM`/`VISIT_TO` — viewings are never booked outside those hours, and half a day of dead entries only made the list longer to walk). The hour is **optional**: a date with no time is stored as plain `YYYY-MM-DD` rather than inventing a midnight viewing, which the server already accepts. A native `datetime-local` was the obvious control and is the wrong one: its `step=300` only drives the spinner, the picker still lists all 60 minutes, and a viewing is agreed on the five. Hour and minute belong in the same control — two selects took more width than the column had and spilled into Statut. A time already in the file that is off the step gets its own option rather than being snapped. Two controls write one field, so a pick made while the previous save is in flight is **queued, not dropped** — re-showing the stored value there would wipe it. Stored as local wall-clock `YYYY-MM-DDTHH:MM` — a viewing is an appointment, not an instant — and parsed with `strptime`, so an impossible date is refused rather than merely shape-checked), statut (`attente` / `visite` / `verifie` / `ecarte` / `promu`). One trap in that grid's CSS: **never name a state class `empty`** — `.empty` is the global "aucun résultat" placeholder (`display:flex; flex-direction:column; padding:60px 20px`), and it silently restyled the visit cell into a 4-line stack. Le **commentaire** is not a column but a **full-width sub-row** under its line (a column would truncate it, and these notes are the reason a lead was kept or dropped). It shows **only for the selected row** — a row selects itself when clicked or when any of its cells takes focus, a click outside the grid clears it, and a freshly added row starts selected — because showing every note at once turned a nine-row list into a wall of text. Clicking **any** cell selects the row and opens its comment — but the two halves of that are not equally safe, and the split is the whole trick. *Opening* the selected row's sub-row moves nothing above it, so it happens immediately (`syncDraftNotes(openOnly)`); *closing* another row's changes the height above the cursor, so it waits for `pointerup` (`notesPending`). A native `<select>` popup opens during mousedown's **default action**, i.e. after our listeners run: shifting the rows there made the Priorité/Statut popup open 60 px from the cursor and the pick silently did nothing. Deferring only the closes fixes it, and the flush on release cannot accumulate stale sub-rows the way a wait-for-`change`/`blur` hold did. The ↗ link needs the same care for the same reason. The ✉ button lights up when a row carries a note and jumps straight to it. The **↗ next to the lien** opens the ad *and* the row: it selects on `click`, not on the row's `mousedown`, because selecting on mousedown collapses whichever comment is open above, the grid slides up under the pointer and the mouseup lands elsewhere — so the link never opened at all. Saves on blur, Échap annule, and `note` is capped at 4 000 characters where the other text fields stop at 500. **Nouvelle annonce** sits *under* the grid, next to where the new row actually appears. A new row is born `attente`, so with that status filtered out it was created, selected and focused **invisibly** — the button looked broken. It is now shown whatever the filter says (`draftForceShow`, one row, cleared as soon as the filter is touched), and the progress line admits it: « dont 1 nouvelle hors filtre ». The tab badge counts the `attente` rows. **Two rows of toggle chips filter the list — Statut and Priorité** (`renderFilterChips()` / `chipGroup()`), not a single-choice select — several statuses read together ("à vérifier + visite prévue") is how the list is actually worked; a **master chip** leads the row — *Tout cocher* ticks all five, *Tout décocher* clears them — and nothing ticked means everything shows (the row says « aucun filtre » so an unticked row never reads as "everything is hidden"). The two dimensions combine in **AND** (statut ET priorité), the values inside one dimension in **OR**; the priority row includes a **« — »** chip for rows not triaged yet. Saved as `statuses` / `priorities` in `hh-drafts-view`, and the old single `filter` value still reads back as a set of one. Numbers accept French input (`742 000`, `148,5`), and a **price under 10 000 is read as thousands** (`749` → 749 000 €) because that is how ads are read and typed — the grid shows the full number straight back, so the correction is visible rather than silent. **€/m²** is a read-only column derived server-side from price ÷ surface habitable (`draft_price_m2()`, never stored, so it cannot drift from the two cells beside it). **Ville** and **Agence** are autocompleted from `<datalist>`s served with the payload (`draft_cities()` / `draft_agencies()`, both via `dedupe_suggestions()` on a loose key so "Saint Germain en Laye" and "Saint-Germain-en-Laye" don't both show up): towns come from `towns/*.md` first, then researched listings, then names already typed; agencies come from the listings (passed through `short_agency()`, which cuts the legal tail — a dossier's "Foncia Transaction Marly-le-Roi (FONCIA TRANSACTION FRANCE, RCS …)" is unusable in a grid cell) then from what was typed, left verbatim. They suggest, they never constrain: both fields stay free text. **Click any column header to sort** (again to flip direction, Code returns to the natural order); the sort is transient like the Villes ciblées one, blanks always sink to the bottom, and Statut sorts along the workflow rather than the alphabet.

**Both grids sort on several levels.** Clicking a new column demotes the one you were sorting by instead of discarding it: sort by prix, then by ville, and the rows inside each ville stay in price order. Re-clicking the current column only flips its direction and leaves the demoted ones alone. **Annonces keeps two levels; Brouillons keeps the last three columns clicked** (`draftSorts`, primary first, `DRAFT_SORT_DEPTH = 3` — a fourth click pushes the oldest out), so "statut, puis ville, puis prix" nests all three. The demoted columns keep a dimmed caret in their header (`.sort-2nd`, and a fainter `.sort-3rd`) with a `2ᵉ/3ᵉ critère de tri` tooltip, so the rule is visible rather than magic. Blanks still sink to the bottom of the primary column, but two blanks are a *tie*, so the next criterion gets to order them.

**Brouillons: sticky header + columns you drag to width.** The grid wrap is a bounded scroll box (`max-height: calc(100vh - var(--topbar-h) - 168px)`) like the Annonces one, so `thead th` can pin with `top: 0` — sticky against the *page* cannot work here, because the wrap has to scroll sideways and an overflow container becomes the scrollport. Each header carries a `.col-resizer` grab zone on its right edge; drag it and that column follows the mouse. Three things make it behave: widths only hold under `table-layout: fixed`, and there an **undeclared column collapses to zero** — so the first drag *seeds every* column from its measured width (`seedDraftColW()`) and the table then sizes itself to their sum (`--dt-w`); the handle must sit **inside** its own cell (all sticky `th` share a z-index, so an overhanging handle is painted over by the next column and cannot be grabbed); and the click that ends a drag has to be swallowed (`colResizeJustDone`) or the release re-sorts the grid. Widths persist per browser in `hh-drafts-view.colw`, are ignored wholesale if a column is added later (the saved map no longer covers the set), are dropped in phone card mode, and **double-clicking any handle restores the defaults**. API: `GET/POST /api/drafts`, `PATCH/DELETE /api/drafts/<id>` — all draft mutations take `DRAFT_LOCK`, because two fast clicks on *Nouvelle annonce* otherwise raced and handed out the same B-code. On a phone the grid becomes one **card per brouillon** (the app's existing mobile idiom — the generic `@media (max-width: 640px)` rule stacks any table into cards, and each draft cell now carries the `data-label` that rule prints), with a **Trier** select standing in for the sortable headers, which are hidden there. A **vue tableau** button (◫, in the header, shown only on touch/narrow devices) puts the real wide grid back on the phone: it sets `data-wide-tables` on the root, and a block at the end of the mobile CSS hands every table its desktop layout again — full-size type, swipe sideways. (Widening the viewport meta, the way "Request desktop site" does, also brings the table back but shrinks 1 238 px of grid into a 390 px screen, which is unreadable.) It is remembered in `localStorage`, and its visibility keys off `screen.width` rather than the CSS width so it cannot hide itself and strand the user. Two traps that block cost real time: the card rule blocks **every** `tr`, so the header row must be un-blocked too or head and body negotiate their column widths separately and never line up; and the wide grid uses `table-layout: fixed`, which reads widths off the header row and shares only the remainder — so **every** column needs an explicit width there, or the undeclared ones collapse to zero.

**When a brouillon earns a real dossier**, write `private/listings/<slug>.md` as usual and set the draft to `promu` (it stays as the trace of where the lead came from).

The dashboard also has a **Villes ciblées** tab that compares target communes side by side, backed by tracked `towns/*.md` files (generic public-record town data — committable, unlike the gitignored `private/` listings). In that tab: **click a criterion's first-column label** to sort the communes by that value (asc/desc; French numbers + star ratings parsed) — **remembered across reloads** like every other list; the user's **personal order is auto-saved on drag-reorder and on show/hide**, and a **↩ Mon ordre** button clears the sort to return to it.

Open APIs — no key; `curl` or WebFetch. `geom` is a URL-encoded GeoJSON `{"type":"Point","coordinates":[LON,LAT]}` (**[lon, lat]**):

- **Cadastre / geometry:** `apicarto.ign.fr/api/cadastre/parcelle` — `?geom=<Point>`, `?code_insee=&section=&numero=`, or `?code_insee=&section=` (whole section). Empty at a point = the pin is on the street.
- **PLU/PLUi (zone + red flags):** `apicarto.ign.fr/api/gpu/{zone-urba,prescription-surf,assiette-sup-s}?geom=<Point>`.
- **Geocode / reverse:** `api-adresse.data.gouv.fr/search/?q=…` · `…/reverse/?lon=&lat=`.
- **Elevation / slope:** IGN RGE ALTI (Géoplateau altimétrie) — sample points along the plot to get the grade.
- **DVF (sales):** `https://geo-dvf.s3.sbg.io.cloud.ovh.net/latest/csv/<YEAR>/communes/<DEPT>/<INSEE>.csv` — the `files.data.gouv.fr` URL 302-redirects here, so hit the S3 URL directly; filter by `id_parcelle` / `adresse_nom_voie`.
- **DPE registry (ADEME):** `data.ademe.fr/data-fair/api/v1/datasets/meg-83tjwtg8dyz4vv7h1dqe/lines?size=…&qs=<lucene>` — qs supports `code_postal_ban:92220 AND etiquette_dpe:C AND type_batiment:maison AND surface_habitable_logement:[150 TO 200]` and `numero_dpe:"…"`; omit `select` to get the full record (~200 fields incl. `id_rnb`). NB: dense communes have >10k DPEs — always filter server-side, never page through.
- **Permits:** `france-cadastre.fr/permisdeconstruire/<commune>` and `basedespermis.fr/…` (HTML → WebFetch). PC number `PC 0<INSEE> <YY> <NNNNN>`; granted + decision >~5 months old ⇒ purgé.
- **Risks:** Géorisques (carrières, RGA argiles, mouvement de terrain, BASIAS/BASOL) + the ERP.

Listing portals (PAP, leboncoin, SeLoger, Bien'ici, moteurimmo) block automated fetches (DataDome 403 / captcha — **never solve captchas**) — work from the **pasted text**, or, when the user's **Claude-in-Chrome extension is connected**, read the live page from their logged-in session (title carries price/surface; the contact card names the agency — but the "Informations personnelles" block is the *user's own* PII, do not store it).

**Harvesting portal photos (SeLoger, via the connected browser):** open the media viewer (click the hero / "Afficher les N photos"), then in-page collect the `mms.seloger.com/<path>.jpg` image URLs **with the size query stripped** (`.split('?')[0]`) — the query-less URL returns the **full original** (~1440 px). `fetch()` them in-page (same-session, CORS-ok), concatenate into one length-prefixed `.bin` blob (`[1-byte ext][4-byte len][bytes]…`) and trigger a **single** `<a download>` (one file dodges Chrome's multi-download block; tool results truncate large base64, so don't return the bytes). Then split the `.bin` locally into `private/listings/<slug>/photos/`, naming portal shots **`annonce-NN.jpg`** to distinguish them from the user's own `IMG_*` visit photos. Also record the announce URL in the md (`Source annonce : …`) so it auto-detects in the drawer.

**Row thumbnails, every time.** For a **listing**: pick the shot that shows the **façade** and copy it to `photos/cover.jpg` (`sips -s format jpeg -Z 900 <src> --out photos/cover.jpg` — the resize keeps the grid light and flattens HEIC). Don't trust the portal's first photo: on half the older dossiers it was an interior or the lawn. A quick way to shortlist candidates is to score the images on "sky + foliage in the top third" from a canvas in the browser — **but verify by eye**, because a photo of the garden with no house scores highest of all, and an agency's flat-blue logo scored 0.99 until a colour-richness guard was added. For a **draft**: open its link in headless Chrome, take `og:image` (works across SeLoger, Bellesdemeures, iad; falls back to the largest visible `<img>`), fetch it in-page and write `private/thumbs/<draft-id>.jpg`, then `sips -Z 420` it. Expect a handful of failures — expired ads and portals without `og:image` — they simply show a `⌂` placeholder.

## Self-build — insurance, cost & the human risks

Beyond any single parcel, these decide whether the project _survives_ (French auto-construction reality):

- **Insurance-first, or you can't resell.** You essentially can't get _décennale_ on your own labour, and without it no _dommages-ouvrage_ (mandatory since the loi Spinetta). For **10 years** you remain the legal _constructeur_ (liable to buyers for structural defects), and selling within those 10 years means the notaire flags the missing DO → buyers discount hard or can't get financing. **Mitigation: a hybrid build — insured pros carry the décennale on structure / envelope / RE2020 systems (so DO is obtainable), DIY only the low-risk finishes.** Look into self-build insurers, the _Castors_ model, or a partial DO.
- **All-in, illiquid, overrun-prone money.** Land + a half-built house is nearly unsellable across the ~**32-month** (range 12–84) build → **no exit** if life changes. Budget **25–30% contingency**, viabilisation, taxe d'aménagement, **TVA 20% on materials** (no recovery for an owner-occupier), and double-carry; there is **no CCMI price/delivery guarantee** — you carry overrun and delay risk yourself.
- **Set written exit gates _before_ committing** (e.g. "stop and sell the permitted land if not weathertight by month X, or if the G2 / insurance comes back bad"). The sunk-cost trap is real once ~€200k and 2 years are in.
- **Standing human note — the forums say this ends more projects than technique does.** The difficulty is _psychological_: burnout after ~2 years, the grind of **living in an unfinished house**, and a documented **couple break-point** (_"on commence en couple, le couple ne résiste pas"_ — the build monopolises attention "comme l'arrivée d'un enfant"). So: **sequence a livable core fast**, plan for **32–48 months** not a smooth 5, and if partnered make it a genuinely shared decision.
